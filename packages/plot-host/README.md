# @hatch3d/plot-host

Private local Node host for `@hatch3d/plot-core` sketches. Version 0.1.0 packages the current Hatch3D runner, CLI, and local study viewer. Build the core first, then run `npm run build --prefix packages/plot-host` and `npm run smoke --prefix packages/plot-host`. Neither package is published.

Install both local tarballs in a separate project and set `"type": "module"` in that project's `package.json` for TypeScript sketch imports of the ESM-only core. Import `Sketch` and helpers from `@hatch3d/plot-core`; use `renderSketch`, `inspectSketch`, or `startSketchServer` from `@hatch3d/plot-host`, or run `plot-sketch inspect|render|open path/to/sketch.ts`. The host accepts an absolute or current-directory-relative sketch path. Every render starts a fresh Node child, so source and transitive local imports reload. `open` serves only localhost; `--out` places pins outside the sketch source directory. SVG and PNG exports use the canonical render result.

`plot-sketch open sketch.ts --plotter-upload` is an explicit local option. It also requires `FEED_API_URL` and `FEED_API_TOKEN` in the Node process. The browser receives neither credential. It uploads only after a user action against the current successful render.

Native SVG preparation is another explicit local option: `plot-sketch open family/sketch.ts --plotprep /absolute/path/to/plotprep`. The executable is installed separately; it is not inside the host tarball. In code, pass `plotprepExecutable: '/absolute/path/to/plotprep'` to `startSketchServer({ entry, plotprepExecutable })`. After rendering, the viewer can sort, reverse, merge, or simplify paths, compare the native derivative against the canonical source, and select which SVG to export, pin, or upload. Its PNG uses the selected SVG at the chosen paper theme and pixel scale. A prepared pin keeps `art.svg` and its original `RenderResult` alongside `prepared.svg`, `preparation.json`, and the selected preview. A prepared queue entry carries both source and prepared SVG hashes. Changing the sketch, an imported helper, controls, finishing, or preparation settings invalidates the selection. The canonical render and checkpoint remain unchanged. Preparation checks the resolved static import graph and declared assets; arbitrary runtime file reads are outside this local source-change guard.

With a locally built native executable, `PLOTPREP_SMOKE_BIN=/absolute/path/to/plotprep npm run smoke --prefix packages/plot-host` packs both Node packages, installs them into a fresh external consumer, and exercises real preparation, derivative export, PNG, pinning, and stale-source rejection. It makes no queue upload.

`checkpoint` and `replay` support both in-checkout studies (version 1, retained Git revision) and installed external families (version 2, local npm lockfile v3). For an external family, keep the sketch and assets in a subdirectory beneath its ESM package root, keep output outside that subdirectory, and install `@hatch3d/plot-core` and `@hatch3d/plot-host` as declared runtime dependencies. `plot-sketch checkpoint family/sketch.ts --result output/result.json --out checkpoints` captures source, exact request, lock topology and installed dependency tarballs, then verifies an offline isolated replay before publishing. `plot-sketch replay checkpoints/<id> --out replay` verifies the same SVG and identity without the original project. The archive requires the recorded Node/npm versions and platform architecture; see [checkpoint limits](../../docs/sketch-checkpoints.md). Run `npm run plot-checkpoint:smoke` from Hatch3D to exercise the packed CLI and external replay.
