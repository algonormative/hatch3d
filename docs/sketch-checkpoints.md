# Sketch checkpoints and preservation

`createCheckpoint({ entry, result, outputDir })` captures the whole directory containing the sketch entry, declared asset bytes, a copy of `package-lock.json`, the repository revision, Node version, parameters, seed, optional finishing request, render identity, and canonical SVG. It renders the captured source in a separate checkout of that revision before publishing the directory. A stale `result` paired with edited source fails this equality check. Failed pending directories are removed; existing checkpoints are never overwritten.

The source boundary is the sketch directory plus shared hatch3d code at a clean, locally retained Git revision. Dirty or untracked shared files outside the sketch directory block capture. Symlinks and embedded Git directories inside the sketch are unsupported. Declared assets must live inside the sketch directory. Put outputs outside that directory, preferably in an ignored location. Arbitrary filesystem or network access from sketch code is outside this contract; the source capture cannot make those inputs reproducible.

`replayCheckpoint({ checkpoint, repoRoot? })` checks captured hashes, exact Node version and lockfile, confirms the revision is locally available, clones it into a temporary isolated checkout, overlays the copied sketch at its recorded repository-relative location, and executes that checkout's `cli/sketch/child.ts` with the saved parameters, seed, and finishing request when present. Older manifests without finishing still replay. It compares regenerated SVG and identity with the canonical result before returning. The current workspace supplies `node_modules` through a temporary symlink after lockfile equality is checked. This is local reproducibility with retained Git history and installed locked dependencies, not an offline archive or a fresh install verification. It does not modify the active checkout.

`comparePreserved(before, after, { parts, boundaries? })` reports differences in nominated final visible part paths, their pen assignments and physical pen settings, and page settings. Optional boundaries are a separate assertion over saved region polygons. It reports conflicts without repair. Equal paths do not guarantee equal perceived appearance when surrounding marks change; compare the whole sheet as well.
