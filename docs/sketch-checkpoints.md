# Sketch checkpoints and preservation

For a sketch inside Hatch3D, `createCheckpoint({ entry, result, outputDir })` retains the version 1 format. It captures the whole directory containing the sketch entry, declared asset bytes, a copy of `package-lock.json`, the repository revision, Node version, parameters, seed, optional finishing request, render identity, and canonical SVG. It renders the captured source in a separate checkout of that revision before publishing the directory. A stale `result` paired with edited source fails this equality check. Failed pending directories are removed; existing checkpoints are never overwritten.

The source boundary is the sketch directory plus shared hatch3d code at a clean, locally retained Git revision. Dirty or untracked shared files outside the sketch directory block capture. Symlinks and embedded Git directories inside the sketch are unsupported. Declared assets must live inside the sketch directory. Put outputs outside that directory, preferably in an ignored location. Arbitrary filesystem or network access from sketch code is outside this contract; the source capture cannot make those inputs reproducible.

Version 1 `replayCheckpoint({ checkpoint, repoRoot? })` checks captured hashes, exact Node version and lockfile, confirms the revision is locally available, clones it into a temporary isolated checkout, overlays the copied sketch at its recorded repository-relative location, and executes that checkout's `cli/sketch/child.ts` with the saved parameters, seed, and finishing request when present. Older manifests without finishing still replay. It compares regenerated SVG and identity with the canonical result before returning. The current workspace supplies `node_modules` through a temporary symlink after lockfile equality is checked. This is local reproducibility with retained Git history and installed locked dependencies, not an offline archive or a fresh install verification. It does not modify the active checkout.

For an installed external family, the same commands select version 2. The entry must live in a family subdirectory beneath an ESM package root with direct runtime dependencies on both `@hatch3d/plot-core` and `@hatch3d/plot-host` and an npm lockfile version 3. Capture includes permitted family source and assets, the original `package.json` and lockfile bytes, a rewritten replay package and lockfile, the exact parameters, seed and finishing request, canonical SVG, and one tarball for every installed locked dependency location. The manifest records full npm node paths, names, versions, tarball hashes, toolkit versions, Node/npm versions, platform, and architecture. Nested copies of the same package remain distinct by installation path. Capture verifies an offline isolated `npm ci --ignore-scripts --omit=dev` with an empty cache and an exact SVG/identity replay before atomically publishing the directory. Replay verifies the checkpoint and a second private copy before installing; it does not read the original family project or Hatch3D checkout.

The external source boundary is the family directory. It accepts TypeScript/JavaScript, JSON request data, images, SVG, and text/brief files; it skips `node_modules`, `.git`, output and pin directories and rejects symlinks, hidden files, environment/credential files, and unexpected configuration. Declared assets must resolve within the captured family. Static imports must remain within that family or name a declared runtime dependency; absolute/file imports, computed imports, `require`, and `createRequire` are unsupported. Output must be outside the family. The source limit is 256 files and 20 MiB; the dependency limit is 128 installed packages, 24 MiB per compressed tarball, 160 MiB compressed total, and 256 MiB expanded total. Offline install has a 60-second timeout and render has a 15-second timeout. Unsupported workspaces, link/directory dependencies, missing native optional packages, or a changed runtime fail with an actionable error; replay never falls back to network or lifecycle scripts.

These checks establish replay from captured bytes for trusted sketches on the recorded local runtime and platform. They do not sandbox arbitrary Node code or guarantee that a sketch which reads undeclared filesystem or network data is portable. Keep those inputs as declared family assets. Run `npm run plot-checkpoint:smoke` to exercise a packed external CLI, offline replay after moving the original family, and corruption and boundary probes.

`comparePreserved(before, after, { parts, boundaries? })` reports differences in nominated final visible part paths, their pen assignments and physical pen settings, and page settings. Optional boundaries are a separate assertion over saved region polygons. It reports conflicts without repair. Equal paths do not guarantee equal perceived appearance when surrounding marks change; compare the whole sheet as well.
